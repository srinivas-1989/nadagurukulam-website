Before the pages — cross-cutting rules

Four rules that apply to every page below

These hold across all twelve pages, so they're stated once here instead of repeated twelve times.

CMSSuper Admin edits this directly — text, images, order
Portal-fedReads live from a portal module — never entered twice
Form → moduleA visitor submission that lands in a portal module's inbox
TBDNeeds a decision or real content from you before build

Shared header & footer

Navigation, logo, footer columns, social links and the contact snippet are one CMS record used on all twelve pages — editing it once updates it everywhere, rather than page by page.

Every page carries SEO fields

Page title, meta description and a social share image are editable per page in the CMS. Home, Courses, Faculty, Events and Gallery & News render server-side (Next.js on Vercel) so they're indexable; the rest can follow the same pattern.

"Portal-fed" means read-only on the site

Faculty cards, events, job listings and public documents are never typed into the website separately — they're written once in the admin portal (Users, Events, Jobs, Curriculum) and the public page simply displays whatever is marked public/published.

Every form has exactly one destination

All visitor-facing forms resolve to one of two portal inboxes, so nothing gets lost in email. See the mapping below.
